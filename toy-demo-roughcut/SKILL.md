# 玩具操作视频粗剪

Codex 查看画面做语义判断，本地 FFmpeg 执行。无需 OpenStoryline、剪映或额外模型 API；Codex 分析仍依赖当前会话能力，并非完全离线。Skill 是 8 组前后对比的编辑经验，不是训练好的动作识别模型。

先按 [references/generalization.md](references/generalization.md) 判断当前素材的展示目的、动作依赖和结果，再参考团队习惯。首次使用读 [references/team-style.md](references/team-style.md)；决定动作内部如何省略、如何换款时读 [references/cut-techniques.md](references/cut-techniques.md)。核对总体证据读 [references/eight-pairs.md](references/eight-pairs.md)；写执行计划前读 [references/execution.md](references/execution.md)。八组样片是条件化案例，不是品类白名单或固定分镜。

## 核心取舍

- 剪空桌等待、无结果准备、反复摆正、同义重拍和单纯收拾，不因“手在动”或“画面静止”直接删除。
- 把「动作开始—关键接触/形变/连接—结果」作为理解单元，不要求每个单元一镜到底。已交代对象和关系时，可省略取出、对位、换手等过程；操作教学、首次陌生机构和真实物理效果需要保留更完整的关键过程。关键结果静止显现也可能需要停留。
- 换下一款可跳剪；正在示范装入、吸住或释放时要保留因果。多款保留差异，磁吸保留组合逐步成形。不是所有重复动作只保留一次。
- 默认原顺序和原构图，不自行搬结果到开头做广告钩子，不裁切放大、不补动作、不倒放、不加字幕/音乐/音效/转场；用户另有要求则按要求。
- 先删冗余，再给慢准备动作局部提速；触发、释放、弹射、回弹等物理效果优先原速。不得统一倍速硬凑 30 秒或把加速物理效果当真实速度。样本有加速迹象，但未逐帧还原精确倍率。
- 由当前素材的信息量和用户目标决定时长，不预设20–30秒、固定动作数或压缩比例；既有样片时长仅用于同类素材的回顾比较。

## 实际工作

每个新对话首次调用时，先读 [references/updates.md](references/updates.md) 并检查上游版本；同一对话不重复检查，用户明确要求更新除外。检查失败继续本地任务，不等待更新阻塞剪辑。更新后重新读取安装目录中的SKILL.md，采用实际安装的版本。

用户体验默认是“给素材和要求→交付首版→按反馈修改”。分类、选策略、覆盖检查、复盘和本机经验维护由Codex在当前任务内自行完成，不要求用户填分类表、批准剪辑清单或逐条确认经验。只在缺少必要素材、存在会实质改变结果且无法合理判断的歧义、或宿主权限要求时询问；可逆的剪辑取舍采用保守判断继续。回复聚焦成片与影响使用的重要事项，不展开内部流程。任务结束后没有常驻后台继续运行。

0. 按 [references/local-memory.md](references/local-memory.md) 定位并读取本机偏好和适用经验，再处理素材；当前要求优先于历史。用户反馈和本次验证结果按同一规则自动记录，不要求用户额外说“记住”。
1. 核对素材、时长、音轨、方向与色彩。已给路径就继续，无需重复上传。配对可规范化空格/下划线，有歧义不能静默错配。
2. 通览全片，先识别实际目的和动作链，再标记款式/操作单元、可见结果、冗余和不确定点。新玩具按generalization.md处理，不套最相似玩具的固定流程。`scripts/inspect_video.py` 生成联系表，2秒采样只导航，不能直接当精确切点。
3. 切点附近加密至约0.1–0.25秒或看短视频；快速弹射/小零件要更密。仍看不清就保守保留/标记，别声称已识别。
4. 按 [references/cut-review.md](references/cut-review.md) 建立简短的款式/动作覆盖表，并写源时间剪辑清单：start、end、speed、保留理由。检查覆盖和因果后渲染。用户已要求成片则直接交首版，不额外设强制确认；用户要求“先看计划”才停在计划。
5. 用 `scripts/render_edit.py` 执行并保留 `.edit.json`。它只执行已选区间，不自动识别动作；拒绝覆盖源/已有输出，默认原顺序和原生显示尺寸。别把运动阈值当语义剪辑器。

## 输出与验收

- 保留原生分辨率和构图；显示为2160×3840就输出同尺寸。读旋转信息，不把编码宽高误当显示方向，不做1080p放大伪4K。
- 样本成片全是4K/30fps、BT.709 SDR；原片是旋转的4K HLG HDR。默认按团队做正确SDR色调映射，不能仅改标签。“保留4K”不等于“保留HDR”；用户要求HDR则选preserve-hdr并说明不保留杜比视界动态元数据。
- 原声保留、无新增声音来自用户要求，**不是8条音轨已听审的结论**。变速原声用atempo保音高；关键声画同步。用户要求原速或存在对话时不擅自加速。
- ffprobe检查尺寸/时长/音轨/色彩，全片解码，查看切点前后及关键结果，排查闪黑帧、残手和声画错位。能听审则听审，不能就明确未做主观听感验收；编码成功不等于风格与人工相同。
- 按cut-review.md核对每个拼接点及各款关键结果。记录实际检查过的项目；低清联系表看不清小零件时局部放大观察，最终成片仍保持原构图。技术检查、画面检查和人工认可分别说明。
- 交付可点击MP4、前后时长、分辨率、速度/色彩变化和不确定点。源素材不改，另存可写目录。

## 快速使用

“使用 $toy-demo-roughcut，粗剪 D:\素材\玩具.mp4，按团队风格保留主要操作、原声和原分辨率。”

需Python 3.10+、ffmpeg/ffprobe，联系表另需Pillow。先检查现有工具，仅安装缺失项。脚本与Skill一起分发，不依赖原作者用户名、临时参考视频路径或其他项目。
