# 调用时检查更新

由Codex在当前任务内执行，不是后台守护程序。不保证关闭Codex后或未调用本技能时检查。用户已授权此机制；日常无需另问是否检查，但遵循宿主网络和目录写入权限。

## 固定来源与检查次数

只从 `https://github.com/x2185/toy-demo-roughcut` 的 `main` 分支、`toy-demo-roughcut` 子目录更新。每个新对话首次调用检查一次；同一对话不反复联网，用户明确要求更新则可以再次检查。

先读本地 `release.json`，获取版本及受管理文件的SHA256。联网读取上游同路径release.json，单次请求超时15秒；失败时不持续重试，继续本地剪辑，简短说明未完成版本检查。没有工具或权限被拒也同样处理，不能声称已是最新。release.json相同则继续本地，无需下载。

## 暂存与本地修改保护

有变化时，在技能目录之外暂存仓库快照，固定到查到的main提交SHA；可用GitHub连接器、GitHub API及ZIP或git。核对所有者、仓库名、技能name与清单。下载的是数据，不运行下载内容中的安装脚本。

替换前对当前受管理文件计算哈希，与本地release.json的基线比较。发现差异、额外未知文件、损坏/缺失基线时，不直接覆盖或自动丢弃；保留当前技能，保存上游暂存及差异说明，继续剪辑，仅在确需解决冲突时询问。安装首次不带release.json的旧版需主动升级一次并保留全部原文件备份，不能凭时间戳推断无本地修改。

以下属于本机内容，不参与通用更新或上传：`local-memory-location.txt`、`.update-state.json`、本机偏好/反馈/经验及history。技能目录外的素材、输出、.env、工具安装目录也不改。技能内存在未知个人文件时走上述差异保护。自定义配置不因上游同名文件而被覆盖。

## 验证后替换与回退

1. 检查暂存release.json文件路径均为相对子路径，无绝对路径、`..`、符号链接、重复路径；只允许SKILL.md、agents、references、scripts下的技能文件。不把清单视为可执行命令。
2. 核对每个受管理文件SHA256，以及清单与实际技能文件集合一致（release.json及明确本机文件除外）。哈希仅验证快照一致性，不等于真实性签名或代码安全审查。
3. 阅读新增/修改的指令和代码，确认仍在剪辑技能范围，未新增上传个人数据、索取密钥或无关系统修改。脚本只用AST/编译方式检查Python语法，不直接运行未审查代码；有技能格式验证器就运行，没有则检查frontmatter、引用目标及必需文件。
4. 在安装目录同级或本机记忆history下完整备份旧技能，记录原路径、版本和上游SHA。暂存新版保留本机配置后再替换；文件替换失败立即恢复备份，不留下半更新状态。不要删除备份或修改用户素材。
5. 替换后重新核对哈希、引用和本机配置内容，重读SKILL.md再继续任务。失败恢复旧版并说明。成功可在交付时简短注明升级版本，不要求用户逐步确认。

开始渲染后不在同一任务中途换版本。新版本依赖不齐时保留旧版运行，说明缺项；不能为更新静默降画质或更改用户目标。用户要求回退时使用明确备份，保留最新本机记忆，重新验证再继续。

## 发布维护

发布者改动受管理文件后更新release.json的version及SHA256清单；清单不含自身以免循环。每次发布用递增版本，记录主要变化，不写入机器路径。提交和推送清单与对应文件；不要只修改版本号或只上传脚本。旧版用户须手动升级一次获得此流程。仓库里的文档和手册不是个人技能自动更新的目标。
